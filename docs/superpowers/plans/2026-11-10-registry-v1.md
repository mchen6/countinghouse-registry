# countinghouse-registry version 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the version-1 registry: an MCP Registry–compatible read API over a mirrored official catalogue, operator-only local publishing of countinghouse modules with their records, the registry side of "enable through countinghouse" for remote entries, and the CLI that generates and publishes module entries.

**Architecture:** An npm-workspaces repository with two packages. `countinghouse-registry` is one Node process (Express 4 app, mirror scheduler, SQLite store through sqlite3). `countinghouse-registry-cli` holds the code both need (canonical hash, `server.json` validation, record schema) plus the generator, publish and operator commands, with ajv as its only runtime dependency. The service requires the CLI package for the shared code.

**Tech Stack:** Node ≥ 24 (CommonJS), Express 4, ajv 8 (draft-07 instance for `server.json`, 2020-12 instance for our own schemas), sqlite3 `^6` (WAL, FTS5 trigram), `node:crypto` (Ed25519, ECDSA P-384, HS256), mocha 11, supertest 7, eslint 9.

**Spec:** `docs/superpowers/specs/2026-11-10-registry-design.md` (cited as "spec §n"). Research: `docs/notes/2026-11-10-mcp-registry-spec-research.md`.

## Global Constraints

- Node `>=24.15`; CI matrix Node `24.15.0`, `24`, `26` on `ubuntu-latest`.
- Dependencies limited to what countinghouse already uses: express `^4.22.2`, ajv `^8.17.1`, ajv-formats `^3.0.1`, sqlite3 `^6.0.1`, mocha `^11.8.0`, supertest `^7.2.2`, eslint `^9.39.5`. No other runtime dependency; no Redis; no JWT, semver or HTTP-client library. The CLI's runtime dependencies are ajv and ajv-formats only.
- License Apache-2.0 in both packages; `"private": true` only on the root.
- Lint rules, exactly countinghouse's five: `no-var`, `prefer-const`, `prefer-arrow-callback`, `prefer-template`, `no-prototype-builtins` (ecmaVersion 2022, commonjs).
- Every change starts with a failing test; explicit `git add <paths>`; commits end with `Co-Authored-By: Claude <model> <noreply@anthropic.com>` only.
- One PR per task (Tasks 1–2 may share one); branch from master; `gh pr create --base master`; `/code-review medium` before reporting; report sha, parent, `git diff <parent> <commit> | sha256sum`, test totals, the code-review line. The reviewer merges.
- Tests that listen on a port use 9700–9719 only, under the shared lock (Task 1's `scripts/with-suite-lock.js`). Never `pkill -f`. Nothing touches `~/countinghouse` except reading files to copy.
- Files copied from elsewhere carry a header naming source repo, path and commit: countinghouse at the commit read when copying; the official registry at `7e8fa024`.
- Public names (spec §8.5), verbatim: our `_meta` key `io.github.mchen6/countinghouse-registry`; pointer subkey `io.github.mchen6.countinghouse`; extension prefix `/v0.1/x/io.github.mchen6/countinghouse-registry` (written `X` below) and the same under `/v0`.
- Mirror User-Agent: `countinghouse-registry/<version> (+https://github.com/mchen6/countinghouse-registry)`, `<version>` from the service's `package.json`.
- Current schema URL: `https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json`.
- No token, signature, key, secret or record body in any log line or error detail.

## Review Focus

1. **Path segments with encoded characters** (`io.github.a%2Fb`, versions with `+` sent as `%2B` or raw `+`): a reader expects the record, not a 404. Pinned in Task 3 (`decodes %2F and %2B in path segments`).
2. **A restart during the first sync or in the middle of an incremental run**: expected to resume from the last applied page without losing or duplicating records, and without moving the checkpoint. Pinned in Task 4 (`resumes after a crash between pages`).
3. **Two writes racing a gateway poll** (one starts before the poll, commits after): the gateway must see it on its next poll. Pinned in Task 8 (`a write committed after a poll's snapshot is returned by the next poll`).
4. **Huge or hostile bodies** on publish, record PUT and results (1 MiB + 1 byte, 501 tools, deeply nested JSON): 413, or 422 for invalid input, never a crash or a slow parse holding the writer. Pinned in Tasks 5 and 8 (`413 over 1 MiB`, `413 over 500 tools`, `a body of deeply nested arrays … stays up`).
5. **A config file that is almost right** (unknown field, claim without trailing `/`, duplicate instance id, interval 9 minutes, secret file mode 0644): startup refused naming the field, never a half-running service. Pinned in Task 2 (`refuses …` cases) and Task 6 (`refuses a group-readable secret file`).
